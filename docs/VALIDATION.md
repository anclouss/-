## Исправление подтверждённого TypeError PyAV

Воспроизведено точное несовместимое API: `faster-whisper 1.2.1` передаёт `metadata_errors` в `av.open`, а PyAV19.0.2 удалил этот аргумент. Это вызывало `STT_INFERENCE_UNKNOWN / TypeError` после успешной загрузки любой модели. Тот же настоящий WAV на PyAV18.0.0 успешно декодируется. В `requirements.in` и lockfile закреплена `av==18.0.0`; другие версии зависимостей не изменились.

Новые два теста реального декодера сначала упали на PyAV19, затем прошли на18: PCM16 mono16k с проверкой значений и stereo48k→mono16k с проверкой обоих исходных тонов. Полный набор: **92 passed, 3 subtests passed**. Настоящая короткая речь декодирована в176000 сэмплов; FeatureExtractor выдал80×1101; Silero VAD нашёл1 речевую область. Полное распознавание текста с весами модели этим прогоном не заявляется.

`check-whisper.py --native-only` теперь включает настоящее чтение WAV до загрузки модели. Добавлен адресный код `STT_INFERENCE_AUDIO_VERSION` вместо потери причины этого TypeError. Отдельный самостоятельный CMD устанавливает av18 только в `.venv`, проверяет WAV и вызывает существующую кнопку запуска; он не изменяет данные, ключи и веса моделей. Перед исправлением приложение нужно остановить. Проверены фактическая Python-проверка из CMD, синтаксис встроенного PowerShell и ZIP; исполнение CMD на Windows здесь не выполнялось.
