# ClipForge AI Video Editor

Локальное приложение для работы с длинными видео: автоматические моменты, неразрушающий монтаж, AI-чат в редакторе, timeline, субтитры и отдельный фоновый Export. Существующий проект расширен; данные и старые MP4 мигрируют без создания нового проекта.

[Как пользоваться редактором](docs/AI_EDITOR.md) · [Архитектура](docs/ARCHITECTURE.md) · [Аудит и план миграции](docs/AUDIT.md) · [Результаты проверок](docs/VALIDATION.md)

## Что умеет приложение

- Загрузить файл либо поддерживаемую публичную запись YouTube/Twitch; открыть исходник или найти автоматические моменты.
- Сохранить монтаж из source-сегментов: trim/cut/split, перестановки, скорость, crop/layout, zoom, текст, звук и субтитры без перезаписи исходного видео.
- Запросить правку обычным текстом. LLM возвращает проверяемые actions; пользователь смотрит предложение и применяет или отменяет его.
- Использовать playhead/выделение и поиск по транскрипции для контекстных команд.
- Автоматически сохранять документ, историю и чат; Undo/Redo/Reset работают с серверными snapshots.
- Быстро смотреть source/proxy preview, при необходимости заказывать обработанный preview и финальный Export отдельно.
- Выбирать разрешение, FPS, платформу, качество, субтитры и watermark; скачивать готовые файлы после фоновой обработки.

Это однопользовательский инструмент на одной машине. Нет аккаунтов/биллинга и публичного SaaS-развёртывания. Viral Score — редакторская оценка, не прогноз просмотров. LLM не заменяет проверку готового ролика.

## Требования

- Python **3.12**, Node.js **22/24**, npm.
- FFmpeg/FFprobe в `PATH`: нужны H.264/AAC, `libass`, `loudnorm`; для H.265 — `libx265`.
- Для локального AI — память/CPU и интернет для первой загрузки Whisper/Ollama-моделей. Для 7B-модели разумно иметь 16 ГБ RAM; час видео на CPU может обрабатываться дольше часа.
- По умолчанию до 4 ГБ на файл и до 12 часов исходника. Общая квота диска не заменяется этим лимитом: оставляйте место для моделей, proxy и экспортов.

Секреты задаются только сервером. Не добавляйте API-ключи в `VITE_*`, Git или чат.

## Windows: запуск одной кнопкой

Распакуйте **весь проект** в отдельную папку и дважды нажмите **`Запустить ClipForge.cmd`**. Не запускайте его внутри ZIP и не переносите отдельно от проекта.

При первом запуске сценарий:

1. Проверяет Python3.12, Node.js и FFmpeg; недостающие инструменты устанавливает через официальный `winget`.
2. Создаёт `.venv`, устанавливает зафиксированные зависимости, проверяет нативные библиотеки и реальное чтение WAV, собирает frontend.
3. Создаёт `.env` только при его отсутствии; имеющиеся настройки и данные сохраняет.
4. Для выбранной локальной Ollama проверяет сервис/модель и при необходимости готовит их.
5. Запускает API и один worker, открывает браузер после HTTP-проверки.

Первый запуск требует интернета, может загрузить несколько ГБ и показать стандартный запрос Windows на установку. Whisper скачивает выбранные веса при первой транскрипции. При OpenAI нужен собственный ключ; сценарий его не создаёт и не меняет AI-режим незаметно.

**Оставьте окно запуска открытым. Остановка — `Ctrl+C`.** Логи: `.logs`. Повторный щелчок открывает работающий экземпляр вместо второго воркера. В этом режиме сам FastAPI обслуживает собранный frontend, отдельный Vite не нужен. `HOST` должен быть `127.0.0.1` или `localhost`; порт по умолчанию8000.

CMD разрешает сценарий только в дочернем PowerShell-процессе; системную политику не меняет. Политики организации сохраняют приоритет. Если они блокируют запуск, используйте разрешённый администратором способ и ручные команды ниже. Нативное выполнение Windows нужно проверять на Windows; Linux-проверка синтаксиса не заменяет его.

## Windows: ручная установка

PowerShell, корень существующего checkout. Дополнительный Git worktree не нужен.

```powershell
winget install --id Python.Python.3.12 -e
winget install --id OpenJS.NodeJS.LTS -e
winget install --id Gyan.FFmpeg -e
winget install --id Ollama.Ollama -e
```

Откройте новое окно после установки и проверьте `py -3.12 --version`, `node --version`, `ffmpeg -version`, `ffprobe -version`. Затем:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
npm.cmd ci --prefix frontend
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
ollama pull qwen2.5:7b
.\scripts\start.ps1
```

Ollama должна быть запущена как приложение/служба либо через `ollama serve` в отдельном терминале. Для ручного режима разработки launcher запускает API, worker и Vite. Если PowerShell-скрипты запрещены, используйте три терминала из корня:

```powershell
# Терминал1
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
# Терминал2
.\.venv\Scripts\python.exe -m backend.app.worker
# Терминал3
npm.cmd --prefix frontend run dev -- --host 127.0.0.1
```

При другом порте API задайте `VITE_API_PROXY_TARGET` для Vite, например `$env:VITE_API_PROXY_TARGET="http://127.0.0.1:8001"`.

## Linux / macOS

Установите Python3.12, Node.js и FFmpeg средствами ОС. Из корня checkout:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
npm ci --prefix frontend
test -f .env || cp .env.example .env
ollama pull qwen2.5:7b
bash scripts/start.sh
```

Для установки Ollama используйте официальный источник либо выберите облачный анализ. Сервис Ollama запускается отдельно. Для работы без Vite соберите frontend **до** запуска API:

```bash
npm --prefix frontend run build
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
# В другом терминале из корня:
.venv/bin/python -m backend.app.worker
```

## Обновление существующей установки

1. Остановите приложение через `Ctrl+C`, дождитесь остановки worker.
2. Сделайте резервную копию `.env` и всего `data`. Для резервирования базы остановите и API.
3. Скопируйте новые исходные файлы в ту же папку. **Сохраните `.env` и `data`; не заменяйте `.env` шаблоном.**
4. Запустите обычную кнопку: зависимости и frontend обновятся по изменившимся файлам.
5. Откройте старый клип: backend добавит таблицы/колонки и лениво создаст монтажный документ. Прежний MP4 остаётся доступен.

Миграция не удаляет проекты/источники и не выполняет Git reset. Особенность старых клипов с удалёнными паузами описана в [аудите](docs/AUDIT.md): старый MP4 сохраняется, но несохранённую карту прежних cuts нельзя восстановить из одного флага.

## Настройки AI и переменные

Чат и смысловой отбор используют **тот же `ANALYSIS_PROVIDER`**. Дополнительный обязательный API-ключ для нового редактора не появился. Ручные безопасные actions и экспорт не требуют LLM, однако выбранный launcher может предварительно готовить настроенную локальную модель.

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `DATA_DIR` | `./data`, относительно корня проекта |
| `HOST`, `PORT` | `127.0.0.1`, `8000` для launcher |
| `MAX_UPLOAD_GB` | `4`, лимит одного источника |
| `MAX_CLIPS` | `5`, число автоматических моментов |
| `RETENTION_DAYS` | `7`, срок хранения старых исходников |
| `FFMPEG_THREADS` | `2`, ограничение потоков кодирования |
| `TRANSCRIPTION_PROVIDER` | `local` или `openai` |
| `WHISPER_MODEL` | `small`; для первого теста быстрее `base` |
| `WHISPER_DEVICE`, `WHISPER_COMPUTE_TYPE` | Опционально `cpu`, `int8`; GPU настраивается отдельно |
| `WHISPER_CACHE_DIR`, `HF_HOME` | Опциональные пути кэша; по умолчанию внутри `DATA_DIR/models` |
| `ANALYSIS_PROVIDER` | `ollama` / `openai` / `heuristic` |
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL` | `http://127.0.0.1:11434`, `qwen2.5:7b` |
| `OPENAI_API_KEY` | Только для выбранных OpenAI-режимов, значение хранится сервером |
| `OPENAI_MODEL` | `gpt-4.1-mini` для анализа/чата |

Полный безопасный шаблон: [.env.example](.env.example). Настройки моделей, сохранённые через UI в SQLite, могут иметь приоритет перед исходными `.env`-значениями. Проверьте страницу настроек после смены конфигурации.

| Режим | Что нужно |
| --- | --- |
| Локальные речь + семантический чат | Whisper-веса, доступная Ollama и выбранная LLM; платный API не нужен |
| Локальная речь + OpenAI-анализ | Whisper-веса и собственный OpenAI-ключ |
| OpenAI речь + анализ | Собственный ключ и оплачиваемые API-запросы |
| Явный `heuristic` | Базовый автоматический отбор без понимания контекста; семантический AI Chat недоступен |

AI может предложить уточнение вместо монтажа. Он не должен угадывать визуальные события, если в доступных данных нет доказательств.

## Хранение и эксплуатация

`data` содержит SQLite, источники, слова, сигналы, waveform, proxy, editor manifests и результаты. Источник не переписывается при монтаже. Документ, история, chat/proposals и экспортные задания хранятся отдельно; завершённый Export соответствует snapshot, а не будущим изменениям редактора.

Один OS-lock не допускает двух тяжёлых workers одной базы. Воркер может продолжать работу после закрытия браузера. Отмена FFmpeg останавливает дочерний encode; отмена STT/LLM кооперативная, а уже отправленный внешний запрос может завершиться. Активный проект сначала нужно отменить и дождаться остановки перед удалением.

Очистка исходников выполняется при старте worker и периодически по `RETENTION_DAYS`. Готовые экспорты остаются; после удаления source нельзя создать новый preview/render. Редактирование и хранение требуют свободного места, лимит одного файла не является общей дисковой квотой.

Приложение не имеет авторизации. Не выставляйте порт в интернет: публичный сервис требует аккаунтов, разделения файлов, HTTPS, квот и изолированных workers.

## Проверки

Из корня после установки зависимостей:

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check backend/app
npm.cmd --prefix frontend run typecheck
npm.cmd --prefix frontend run lint
npm.cmd --prefix frontend run test
npm.cmd --prefix frontend run format:check
npm.cmd --prefix frontend run build
```

Проверка настоящих моделей: короткое видео с речью → сохранённая транскрипция → команда чата → предложение/Apply → обработанный preview → Export → воспроизведение MP4. Тесты с подменённой внешней LLM проверяют интеграцию и валидацию, но не доказывают качество модели. Один HTTP200 не подтверждает весь pipeline.

Проверены backend-тесты, 8 frontend-тестов, lint/typecheck/форматирование, production build и работа редактора в Chromium. Отдельный фоновый worker создал настоящий MP4 720×1280, доступный для скачивания после закрытия клиента. Точные результаты и ограничения — [docs/VALIDATION.md](docs/VALIDATION.md). В этой облачной среде загрузка Whisper получила HTTP403 на CDN `us.aws.cdn.hf.co`; это отдельное ограничение среды, не установленная причина ошибки на пользовательском Windows.

## Диагностика и исправление речи

`Проверить распознавание.cmd` проверяет нативные импорты, настоящее чтение WAV и запуск модели/VAD. Для реальной речи перетащите видео на файл. Он не выводит API-ключи или подписанные URL.

В прежней сборке PyAV19 убрал `metadata_errors`, который вызывает faster-whisper1.2.1. Поэтому после успешной загрузки модели происходил TypeError. Исправление — закреплённая **PyAV18.0.0** и реальный regression test декодера. Для старой установки остановите приложение, положите `Исправить распознавание.cmd` рядом с кнопкой запуска и выполните его. Видео/модели/настройки сохраняются; меняется пакет локального `.venv`.

При DLL-ошибке launcher проверяет официальный Microsoft Visual C++ Redistributable x64. Это условное исправление нативной зависимости, а не объяснение любой ошибки Whisper. Не отключайте TLS или проверки файлов для загрузки моделей.

## Удаление Windows

`Удалить ClipForge.cmd` нужно положить рядом с кнопкой запуска и дважды нажать. **Удаляется вся эта папка приложения вместе с `.env`, локальными видео, клипами и моделями внутри неё.** Общие Python/Node/FFmpeg/Visual C++/Ollama и внешние каталоги данных сохраняются. Windows-корзина используется, где доступна; восстановление не гарантируется.

Сценарий проверяет маркеры приложения, защищает системные/пользовательские корневые папки и отказывается проходить directory-junction. Нативное удаление на Windows в Linux не выполнялось. Сохраните нужные видео заранее.

## Стоимость и ограничения

Локальные AI-инструменты не берут оплату за запросы, но используют ваше оборудование/диск/время. Иллюстративный бюджет облачного AI для часа записи — $0,4–1,5 без аренды/хранения; это не текущая котировка. Новые chat-команды добавляют запросы, если их не переиспользовал кэш. Формула и ограничения — в архитектуре.

Face-aware framing здесь основан на редких локальных выборках; нет гарантированного покадрового tracking, распознавания эмоций/событий игры/чата. Browser preview является быстрым монтажным приближением. Семантический чат зависит от доступной LLM; долгие реальные стримы и Windows требуют собственных проверок. Дальнейшее развитие — измерение качества на ваших видео, более точный vision/tracking, затем PostgreSQL/S3 и многопользовательская очередь.
